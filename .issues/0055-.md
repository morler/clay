## 2026-11-16 完成记录

tests/test_subagent.c 新增两类离线压力场景：

1. 一个主会话与四个子代理共用同一 provider/model 和 HTTP scope，mock 21 按请求标记驱动 429 恢复（含一次缺 Retry-After）、todowrite 工具调用与最终摘要，以及一次硬错误。断言 scope 内 HTTP 峰值并发为 1、inflight 归零、重试次数、工具次数、四个子代理结果和落盘 transcript。
2. OpenAI/model-a 与 Grok/model-b 两个会话分别运行四个子代理和主会话，completion hook 断言各自 scope 身份、工具回调和摘要，第二个会话注入一次分支取消并断言其余分支不受影响。两个会话顺序执行，避免触发跨 batch 的全局终端状态竞态。

验证：make -j4 test-subagent 与 make -j4 test 通过；test_subagent 连续多次重复运行通过；Clang ThreadSanitizer 独立构建并运行 test_subagent 无报告；git diff --check 通过。所有密钥为离线占位符，HTTP 由链接期 wrap 拦截，不访问外网。

Windows：本环境缺少 x86_64-w64-mingw32-gcc/strip/pkg-config、Wine 与 UPX，Makefile 的 build-win 无法执行；测试目标依赖 GNU ld --wrap、pthread_barrier、mkdtemp、raise(SIGINT) 等 POSIX/GNU 设施，未配置 Windows 测试构建。因此上述场景只在 Linux 本机验证。

TSAN 另发现既有跨 batch 终端状态竞态（g_pending_escape/g_pending_escape_action），已追加到 clay-m0er；本次压力用例按会话顺序运行，不引入该竞态。
