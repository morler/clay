现状：clay_commands_maybe_compact（src/commands/context.c:1783-1818）用 commands->input_tokens 与 0.9*context_token_budget 比较；但 input_tokens 来自 message.c:1604-1612 对本轮所有 round 的累加（on_usage_details 每个 round 都 +=，message.c:1342-1350），而 src/commands/context.h:236-239 的注释写的是“最后一次请求”。多轮工具调用会把该值放大，导致每次都触发原地折叠，既浪费一次判断又反复重写历史（破坏前缀缓存）。

第二个问题（评审补充）：maybe_compact 只处理 commands->conversation，即上一轮结束时的历史。本轮的增量在 message.c:1528 复制出的 messages 里，工具结果由 openai.c:688-698 写进去，直到 message.c:1604-1605 才回写 commands->conversation。所以“在工具循环内调用一次”按现有签名碰不到本轮内容，单轮 64 次大工具结果依然无法兜住。子代理同理：直接调用会读父会话的 input_tokens，并压缩父会话历史。

本项只做“折叠”（把旧 tool 结果换成短预览），不引入 LLM 摘要。纯文字对话过阈值时没有可折叠内容，这属于预期限制：阈值只用来提醒用户 /compact，不承诺自动保住窗口；真正的自动摘要另立项（见 #85）。

killi 对照：crates/killi/src/agent/compact.rs:60-61 用 stats.context（上次 usage.prompt）+ 只估算未计费后缀，accounted_messages 记录已计费边界。

任务：
1. 增加 accounted_messages / last_prompt_tokens 状态，判断以最后一次请求的 prompt_tokens 加未计费后缀估算为准，修正 context.h 注释。
2. 把折叠函数改成接收“正在使用的 messages 数组 + 上次 prompt_tokens”，并提供一个在每轮发请求前的回调（openai.c 每 round 发送前），子代理传自己的 messages 与自己的计数。
3. 增加确定性测试：伪造 3 个 round 的 usage，断言只有超过预算才折叠；单轮内多次大工具结果被兜住；折叠幂等。

验收：多轮工具调用不再提前折叠；单轮超预算被兜住且折叠的是本轮消息；子代理只折叠自己的历史；测试加入 Makefile 的 UNIT_TEST_TARGETS。

## 2026-11-17 实现与验证

改动：
1. src/commands/context.h 新增 last_prompt_tokens / accounted_messages；src/commands/message.c 的 on_usage_details 记录最后一次请求的 prompt（不再只累加）。
2. clay_commands_maybe_compact 改用「上次计费 prompt + 自 accounted_messages 起的估算」，估算口径与 scope.c 一致（2 字节/token、每条 4 token 开销）。
3. 折叠逻辑抽成 clay_commands_compact_history(conversation, billed, accounted)，可以作用于任意数组。
4. ClayOpenAICallbacks 新增 before_request，OpenAI 与 Codex 在每 round 组包前调用；message.c 在此把要发的 messages 交给折叠函数，子代理传自己的数组与计数。

测试：
- tests/test_context_compact.c 新增多 round 用例：三轮累加 120k 但最后一次 40k 时不折叠，单次 94% 才折叠（红→绿）。
- tests/test_message.c 在一个 mock 轮次里伪造 3 个本轮大 tool 结果，断言 before_request 把它们折叠（旧实现碰不到本轮数组）。

验证：make test 全绿；make test-subagent、test-message、test-context-compact 通过。
未验证：真实 provider 下折叠时机的手感，需要长会话，属 #76 的手动验收。
