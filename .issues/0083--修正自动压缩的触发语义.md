现状：clay_commands_maybe_compact（src/commands/context.c:1783-1818）用 commands->input_tokens 与 0.9*context_token_budget 比较；但 input_tokens 来自 message.c:1604-1612 对本轮所有 round 的累加（on_usage_details 每个 round 都 +=，message.c:1342-1350），而 src/commands/context.h:237-241 的注释写的是“最后一次请求”。多轮工具调用会把该值放大，导致每次都触发原地折叠，既浪费一次判断又反复重写历史（破坏前缀缓存）。另外 maybe_compact 只在每个 user 轮开始调用（message.c:1521），工具循环内部与子代理内部从不调用（subagent.c:172 只用轮数上限）。killi 对照：compact.rs:60-61 用 stats.context（上次 usage.prompt）+ 只估算未计费后缀，accounted_messages 记录已计费边界。

任务：
1. 增加 accounted_messages / last_prompt_tokens 状态，压缩判断以最后一次请求的 prompt_tokens（含未计费后缀估算）为准，修正头文件注释。
2. 在工具循环内部按需检查（例如每 N 轮或每次 tool 结果后估算增长），避免单轮 64 轮溢出上下文。
3. 为子代理接入同一预算逻辑（子代理历史独立）。
4. 增加确定性测试：伪造 3 个 round 的 usage，断言只有超过预算才折叠，且折叠幂等。
验收：多轮工具调用不再提前折叠；单轮超预算仍被兜住；make test 通过。
