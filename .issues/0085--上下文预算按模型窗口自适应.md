现状：src/config.c:225-233 的 context_token_budget 全局固定默认 128k，不按模型区分；读不到值或值 < 1024 都回落 128000，设置函数也拒绝 < 1024（src/config.c:235-238），所以“0 表示关闭”和“未配置”都无法表达。请求体没有 max_tokens/max_completion_tokens（src/providers/openai.c:580-630），输出上限完全交给供应商。

评审结论：不要把 killi 的 60%/85%/输出预留 ÷4 移植过来。killi 的阈值对应“让模型写摘要替换历史”，clay 是折叠旧工具结果，两者不可比；移植只会让人以为窗口会自动保住。

任务：
1. 配置语义：未设置返回哨兵值（如 -1），显式 0 表示关闭折叠，显式值即预算；同步放宽 setter 校验。三种情况都要有测试。
2. 折叠阈值 = 显式预算（默认 128k），不引入窗口百分比。若确实想知道模型窗口，用配置字段表达（对齐 killi 的 config.rs:307 `context_window: Option<u64>`），不做内置模型表。
3. 输出上限：仅在确认字段与供应商兼容后才加——OpenAI 官方用 max_completion_tokens；Codex/Responses 用 max_output_tokens 且 ChatGPT 计划会拒绝该字段（crates/killi/src/llm/responses.rs:50-51 有注释）；其他兼容 provider 按 #108 的 mock 结论。字段名与开关见 #122。

验收：未设置 / 0 / 显式值三条路径有测试；请求体只在确认兼容的 provider 上带输出上限；不出现任何“窗口百分比”逻辑。
