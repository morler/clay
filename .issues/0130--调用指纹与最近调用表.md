## 2026-11-18 实测结论：不实现，关闭

#88 规定"先量，没有证据就关闭本项与 #130-132"。量完了，证据不支持。

**样本**：16 个真实 chat 日志（`~/.clay/chats/*/chat.json`），20 个有工具调用的 turn，**399 次调用**。turn 规模覆盖 1 到 98 次调用，状态含 11 completed / 7 aborted / 2 provider_error，不是只挑成功样本。

**统计**（`scripts/repeat_report.py`，可复现）：

```
20 turns with tool calls, 399 calls total
397 distinct fingerprints (same turn only)

what a breaker at each threshold would have stopped:
  >=2:   0 fingerprints,   0 calls skipped (0.0%)
  >=3:   0 fingerprints,   0 calls skipped (0.0%)
  >=5:   0 fingerprints,   0 calls skipped (0.0%)
  >=8:   0 fingerprints,   0 calls skipped (0.0%)
```

按工具单独看也一样：334 次 `shell_exec` 对应 **334 个不同命令**；`read`/`grep`/`glob` 同样没有同参数重复。也就是说 clay 当前的模型在这些会话里**从不重试同一调用**，killi 的"第 3 次阻断/第 5、3 次警告"在这里没有可拦的对象。

因此不实现指纹表、断路器与近重复警告：#131、#132 一并关闭，#88 关闭。

**脚本保留**：`scripts/repeat_report.py`（无依赖，读 chat.json，按规范化参数聚合同 turn 内的指纹）。将来若换成更容易打转的模型，或日志出现重复，用它重新量一次即可；不接 CI，不设阈值门槛。

**局限（如实记录）**：样本来自单一用户的 16 个会话，且大多发生在同一批开发任务上；模型/provider 组合有限。这足以否定"重复是常态"，不足以断言"永不重复"。
