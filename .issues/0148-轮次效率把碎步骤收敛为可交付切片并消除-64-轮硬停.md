## 背景

64 轮上限是症状，不是根因。当前是三层问题叠加：

1. 任务执行单元按“实现步骤”切，而不是按可验收的垂直切片切，重复读代码/构建/测试。
2. 提示词与工具粒度把一次工作拆成多轮：一轮本可放多个调用，但 97% 的轮只发 1-2 个；82% 的调用是 shell_exec，而 read/grep/edit 都是一次一个目标。
3. 64 轮是硬停点，没有自动续跑/上下文交接；子代理 32 轮耗尽时还会丢掉已有 summary。

本 epic 的目标不是把 64 抬到 128，而是先用测量和垂直切片降低轮次需求，再把硬上限改成软预算 + 可恢复的续跑。

## 基线（2026-11-20，~/.clay/chats 本机样本）

- 20 个 chat / 498 条 assistant 消息 / 769 次调用；2 个 turn 打满 64 轮，6 个 ≥48 轮。
- 每轮调用数：1 个 203 次、2 个 256 次、>2 个仅 13 次。
- shell_exec 633/769（82.3%）；391/633 以 `cd` 开头；shell grep 162 次 vs grep 工具 14 次。
- 一个 64 轮 turn：114 次调用（83 shell + 14 edit + 8 write + 7 read），14 次 edit 分布在 14 个不同路径；另一个 64 轮 turn：95 shell + 2 read。
- #76 子树 67/147 个 issue，51 个 step；43 个已关闭 step 中 19 个与兄弟 item 在同一个提交关闭。

## 验收指标

- 64 轮命中率 ≤5%，≥48 轮占比 ≤10%。
- 每轮工具调用数 ≥1.5，目标 2。
- 每会话固定命令轮次 ≤5。
- shell 调用占比从 82% 降到 <50%。
- 单 issue 对应单提交 ≥80%；新 issue 轮次中位数 20-40。
- 每 issue 完整测试次数 ≤1 次完整 + 目标测试。

## 不做

- 不先把 64 抬到 128；实测一个打满 turn 已消耗约 3.5M input tokens、19 分钟墙钟。
- 不引入新依赖，不把 Clay 改成通用工作流引擎。
- 不重写已关闭的 51 个 step 历史；只防止继续复制这种粒度。
- 不在本 epic 内做 multi-edit、paused checkpoint、LLM handoff；等 P0/P1 指标确认后再建独立 issue。

## 2026-11-23 复检：P1 没有把指标拉回来

复检时 `scripts/round_report.py` 的结果（25 chats / 23 turns）：

- rounds/turn：median 17、p90 61、max 65；≥48 5 turns（21.7%）、≥64 3 turns（13.0%）。
- calls/message 1.56；0/1/2/3+ calls 的 assistant 消息为 28/262/336/17。
- tools：shell_exec 81.7%，read 10.4%，edit 2.7%，grep 1.4%。
- multi-target（`paths`/`edits` 长度 >1）为 0；#151 的 schema 上线后没有一个真实调用使用多目标。

最新 64 轮 turn（eefbef5c，11-23 10:45）已经在带 `# Round economy` 的提示词和 multi-target schema 下运行，仍然 64 轮耗尽：64 个 assistant 消息、103 次调用，其中 38 轮只发 1 个调用；71 次 shell_exec、9 次 edit、8 次 read、1 次 todowrite；9 次 edit 分布在 3 个文件，6 次改同一个文件。结论：只在提示词里写“批处理”并加 schema，不能改变模型的单步习惯。

本次修正：

1. 预算不再等到 64 才说话：#155 在 16/32/48 轮各注入一次收敛提示，并在耗尽后自动续跑一段、最后无工具收尾。
2. 把“多处编辑”变成一个调用：#157 的 `edit edits[]`，同文件多处替换一次完成，保留单文件 checkpoint/undo。
3. 工具描述而不是 schema 里写明 `read paths[]`/`grep paths[]`/`edit edits[]`；系统提示点名这三个入口。
4. `round_report.py` 增加 multi-target 采用率，用来验证模型是否真的用上新入口。

仍未做：shell_exec `commands[]`/`cwd`（#152）、子代理自动续跑与部分 summary（#154）、同轮只读工具并行。指标要等真实会话按新构建跑过之后再量；本次不声称已达标。
