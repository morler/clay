## 现状

- 每次请求已写入 `~/.clay/chats/<id>/requests.jsonl`（`src/chat.c:430-470`），含 `kind/round/input_tokens/output_tokens/cached_input_tokens/context_budget/duration_ms`。
- `chat.json` 的 assistant 消息含 `calls`，可统计每轮调用数。
- `scripts/repeat_report.py` 只统计重复调用指纹；没有轮次、64 轮命中、shell 占比、每轮调用数等指标。
- 当前结论来自一次性手工统计，无法在每次改动后复现。

## 任务

1. 新增 `scripts/round_report.py`（仅标准库，只读）：
   - 输入 `--root`（默认 `~/.clay/chats`），可选 `--json`。
   - 从 `requests.jsonl` 按 `kind=main` 的 `round` 重置切分 turn，统计：每个 turn 的请求数/轮次、64 轮命中、≥48 轮占比、p50/p90、墙钟时间、input/output token。
   - 从 `chat.json` 统计：assistant 消息数、每轮调用数分布、工具名分布、shell_exec 占比、以 `cd` 开头的 shell 占比、固定命令（issues/git/make 等）轮次。
   - 只输出聚合数字；绝不打印消息正文、命令参数或路径中的敏感内容。
   - 对损坏/非 UTF-8 的 journal 采用宽松读取并计数，不中断报告。
2. 增加 `--self-test` 或内置临时 fixture：构造 2-3 个合成 turn（含 64 轮耗尽、1/2/4 调用、shell/cd），断言统计值。
3. 在 `scripts/` 或 README 记录运行方式；不接入 CI 强制门槛，先作为基线工具。

## 验收

- `python3 scripts/round_report.py --root ~/.clay/chats` 输出当前基线，数字与手工统计一致（至少 20 chat、498 assistant 消息、2 个 64 轮 turn、shell 占比约 82%）。
- `--json` 可被 `jq` 解析；`--self-test` 通过。
- 在含非法 UTF-8 的 chat.json 上不崩溃（可跳过或计数）。
- `git diff --check` 通过；脚本无第三方依赖。

## 不做

- 不改 Clay 运行时，不加新的 usage 字段。
- 不把指标接入生产 UI 或 CI 硬门槛。
- 不读取/输出聊天正文。

## 规模

预计 5-10 轮；涉及 `scripts/round_report.py`，必要时 `Makefile` 加 `round-report` 目标。
