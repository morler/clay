参考 ../neo 的 internal/workflow、internal/tui（workflowBlock、workflow_events.go、statusActivity、resultSummaryBlock）以及 docs/parallel-execution-ui/design.md。目标不是复制 Go 结构，而是让 clay 在这几件事上给出同样清楚的信息：清单是稳定的、进度是实时的、并行是看得见的、turn 结束时说得清结果。

## 差分（2026-11-23 对照代码实测）

| 能力 | neo | clay 现状 |
| --- | --- | --- |
| 清单 | transcript 内稳定块，原地刷新；header 实时 `N/M complete · x failed · y skipped`；运行项带最新工具活动 | 追加式（message.c render_plan）；header 只打一次，统计是首次渲染的快照（clay_plan_header，render/list.c:391）；运行活动只出现在 below 状态行 |
| 完成收据 | `✓ Done · 3/3 verified · 12s`、`✗ Finished with issues · 2/3 complete · 1 failed`、`Paused · reply to continue`；标签回落到 workflow 标题 | `✓ N tools · 12.3s`（set_status，message.c:1023）；无 plan 统计，无失败收据 |
| 同轮并行工具 | 只读调用并发；组块 header + 每调用一行，源顺序固定；状态行 `N tools in parallel` | provider 逐个执行（openai.c:706、openai_codex.c:837）；每调用一行 receipt；无并行 |
| 子代理 | inspect/work 模式；每分支一行（描述 + 实时活动 + 耗时）；inspect 只读、并行安全 | 批量 tasks[] 全部可写；单个 spinner 聚合 `Delegating N branches`；无模式区分 |
| goal | 持久目标 + 自动 continuation | 无 |

## 验收

- 交互模式下清单创建后是稳定块；每次 todowrite 后 header 统计与实际状态一致；运行项显示最新工具活动；失败/跳过不丢行。
- turn 收据包含 plan 的完成/失败/跳过计数；有失败项时是失败态。
- 同一 assistant 消息里的多个只读调用实际并发执行，结果按源顺序进入 messages；界面显示组块而不是 N 条顺序 receipt。
- 子代理支持 inspect 模式（只读工具集）并逐分支显示活动。
- `make test test-pty test-todowrite test-message test-subagent` 通过；提示词预算在 CLAY_PROMPT_AND_TOOL_BUDGET 内。

## 不做

- 不做 goal / 自动 continuation（独立控制状态，不属于可见工作流）。
- 不把 todowrite 改成 neo 的 id-based workflow 工具；整表重写保留，行为等价且模型接口更简单。
- 不做 below 区域的清单面板；清单留在 transcript。
- 不引入 markdown 渲染器或新 TUI 框架。
