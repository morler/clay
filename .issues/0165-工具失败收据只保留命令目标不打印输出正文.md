## 现状

- 失败调用会打印两条信息：`✗ Failed ...` 的 receipt 行，加上 `print_tool_failure`（src/commands/message.c:1261）打印的 `$ 命令` 与前 8 行输出（`CLAY_TOOL_VISIBLE_LINES`，message.c:14 附近）。
- 成功调用已经只有单行 receipt；`read` 的正文、`shell_exec` 的 stdout 都不显示。
- 失败时 `shell_exec` 的 label 只有 `Failed`，不带命令；命令只出现在被删掉的那条 print_tool_failure 行里。
- 其他工具的 label 已经带目标（`read`/`write`/`edit` 的 path、`grep`/`glob` 的 pattern），失败原因（error）在 `error_in_label` 分支里进入 label。
- `tests/test_message.c:340-390` 断言失败时输出正文可见（`boom line`、`boom`），与本任务冲突。

## 任务

1. 删除 `print_tool_failure` 与 `CLAY_TOOL_VISIBLE_LINES`：失败不再打印输出正文，也不额外打印 `$ 命令` 行。
2. `tool_label` 的 `shell_exec` 失败分支显示命令：`Failed $ <command>`（与成功的 `Ran $ <command>` 对应）。
3. 保证单行仍包含可行动的信息：失败原因（error 或 exit code）已经在 label；未知工具等没有 label 的路径补上 error，不让失败静默。
4. 同步 README「Quiet, scannable work」一段：失败只保留单行 receipt，不显示输出正文。
5. 更新测试：失败 read 不出现 `boom line`，失败 shell 不出现 `boom`，但仍包含 `$ false` 与 `exit 1`。

## 验收

- `tests/test_message.c`：成功/失败 read、成功/失败 shell 各只输出一行；失败行带命令或目标与失败原因；不含输出正文。
- `make test-message` 通过；`make test` 通过。
- 手工：`read` 一个不存在文件、`shell_exec` 跑 `false`，屏幕上各只有一行。

## 不做

- 不改工具返回给模型的 JSON（输出仍完整进入 messages）。
- 不改权限拒绝与 Plan 模式的提示路径（它们本来只有一行）。
- 不做「显示更多输出」的开关；需要完整输出时由模型重新读取或运行。

## 规模

预计 4-6 轮；涉及 `src/commands/message.c`、`tests/test_message.c`、README.md。
